1. Despliegue y Escalado Independiente

El sistema de chat (WebSockets) genera una carga continua muy distinta al sistema de publicación de lotes. La arquitectura de microservicios nos permite escalar horizontalmente el Chat Service sin desperdiciar recursos duplicando todo el sistema (como pasaría en un monolito).

2. Bases de Datos Políglotas

No existe una base de datos "perfecta" para todo. Para usuarios e inventario usamos PostgreSQL (relacional, ACID). Para el chat rápido usamos MongoDB (documentos). Y para el manejo de sesiones y conteo de tokens del Gateway usamos Redis.

3. Comunicación Orientada a Eventos

Cuando un comercio confirma un rescate, no hacemos una llamada sincrónica lenta que bloquee al usuario. El Lots Service simplemente dispara el evento LotDelivered al Bus (Kafka). El Impact Service lo escucha en segundo plano y actualiza el CO₂ ahorrado.

4. Gateway Unificado

Las aplicaciones cliente (Móvil y Web) no necesitan saber que existen múltiples servicios. El API Gateway unifica todos los endpoints, maneja la validación inicial de tokens JWT y protege los servicios internos contra ataques DDos (Rate Limiting).
